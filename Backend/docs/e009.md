# E0-09 #350: parametros con vigencia y banderas

## Integración de banderas en rutas pendientes

La corrección parte de `origin/develop` en `f96b9a08c6932dc3daac373ea5ab632383b2fbf3`.
El control ejecuta `requiere_funcion(clave)` al alcanzar el 501 interno existente.
Consulta el valor persistido vigente en la fecha de Guayaquil, con prioridad para la
agencia operativa autenticada cuando existe. ATM usa alcance global porque su sesión
autenticada no tiene un contexto de agencia. Una bandera apagada, inexistente o
inválida cierra la rama con `404 FUNCION_NO_DISPONIBLE`. La implementación pendiente
conserva ese resultado con la bandera activa o con la lectura SQL indisponible.

| Rama pendiente | Clave |
|---|---|
| ATM, transferencia / reverso / retiro | `FUNCION_ATM_TRANSFERENCIA` / `FUNCION_ATM_REVERSO` / `FUNCION_ATM_RETIRO` |
| Caja, depósito / retiro sin dependencias financieras | `FUNCION_CAJA_DEPOSITO` / `FUNCION_CAJA_RETIRO` |
| Transacciones, reverso sin dependencias financieras | `FUNCION_TRANSACCION_REVERSO` |
| Contabilidad, baja de cuenta | `FUNCION_CONTABILIDAD_BAJA_CUENTA` |
| Parámetros y Catálogos, cambios de comisión sujetos a aprobación | `FUNCION_PARAMETRO_APROBACION` |

Las cuatro claves existentes conservan sus semillas. Las nuevas claves carecen de
semilla y se resuelven como apagadas mientras estén ausentes. Las operaciones con
implementación disponible conservan su flujo y sus controles, incluida la auditoría
de intentos fallidos para las ramas pendientes.

WorkOS sigue autenticando. CreadoPor registra el sujeto WorkOS validado por el consumidor;

Uso desde un servicio con una Connection y transaccion propias:

    from app.modules.parametros import general as Parametros
    vigente = Parametros.valor(conn, 'SES_INACTIVIDAD_MIN', fecha, agencia)

valor resuelve el override vigente de la agencia y, si no existe, el valor global.
Los limites de fecha son inclusivos. Fechas de negocio: America/Guayaquil o fecha
contable indicada por el modulo; no se usa la fecha UTC como sustituto silencioso.

registrar guarda un intervalo explicito y rechaza solapamientos con 422 VIGENCIA_SOLAPADA.
programar crea un sucesor y cierra atomicamente la vigencia anterior el dia previo.
No permite reemplazar un inicio existente ni insertar antes de un sucesor activo.
Guarda la frontera anterior para permitir una cancelacion correcta en E1-10.
Los consumidores no deben confirmar una transaccion cuya escritura haya fallado.
El servicio no hace commit: el cambio y la auditoria del consumidor se confirman juntos.

Tipos: Entero estricto, Decimal sin exponente y con hasta cuatro decimales, Texto,
Booleano canonico true/false, Hora HH:MM y Lista JSON de textos. ValoresPermitidos
es una lista JSON opcional de opciones tipadas; para Lista limita sus elementos.
No es un segundo catalogo comercial. Decimales se calculan con Decimal, nunca float.

requiere_funcion(clave) es una dependencia FastAPI. Falta de valor, parametro inactivo
o bandera apagada producen 404 FUNCION_NO_DISPONIBLE antes del cuerpo de la ruta.
Solo un Booleano verdadero habilita. Una configuracion de tipo corrupto no habilita.
No se modifican automaticamente constantes, sesiones WorkOS ni rutas de otros equipos.
Las banderas ATM y de aprobacion de comisiones se siembran apagadas; integrar cada
consumidor exige respetar su contrato y pasar sus regresiones.

## SQL y compatibilidad

Tres migraciones aditivas bajo migrations/cooperativa: estructura, semillas y referencia inactiva de hora de corte. Esta ultima copia el calendario real sin cambiarlo; no sustituye su consumidor contable.
El ejecutor debe fijar migration_database en SESSION_CONTEXT a la base verificada.
Las migraciones usan XACT_ABORT, transaccion y rollback; no contienen DROP ni ALTER.
Una instalacion parcial falla en vez de repararse silenciosamente. El indice y el
trigger se crean solamente en tablas nuevas; Organizacion.Agencia no se modifica.
El trigger evita solapamientos inclusive en escrituras SQL directas. El servicio
serializa por la fila de Parametro con UPDLOCK/HOLDLOCK, sin cache entre peticiones.

Rollback de despliegue: deshabilitar consumidores nuevos y conservar las tablas y su
historial. Un fallo anterior al commit revierte su migracion. No hay borrado automatico.
La aprobacion para DDL de desarrollo no autoriza produccion ni alterar tablas ajenas.

su comportamiento. Los clientes externos que comparen literalmente 501 o el codigo

compatibilidad binaria con el error antiguo.
El cliente compartido de la SPA conserva el mensaje de ProblemDetails y el plan de
cuentas lo muestra mediante fallback. Su helper esNoDisponible aun reconoce 501 y
404 generico; no clasifica el codigo nuevo, pero tampoco lo oculta ni lo interpreta
como exito. No se requiere cambiar pantallas ni tocar una rama frontend.
